# 智慧化配置（Smart Capabilities）功能说明与测试指南

本文档面向不熟悉 BitFun 的用户，介绍「设置 → 智慧化配置」分类下每个功能页的作用、适用场景，以及如何进行最小化的可用性测试。

「智慧化配置」分类当前共包含 7 个配置页：

1. 个性化
2. 权限管理
3. 快捷动作
4. 审核
5. 记忆
6. 外部 AI 应用
7. MCP

> 入口：打开 BitFun，进入「设置」页，在左侧导航的「智慧化配置」分类下选择对应 Tab。
>
> 说明：本分类历史上还曾存在 Computer use、浏览器控制、调试模式设置、审核员阵容等子模块，目前已从该入口移除或收敛；下文不再展开。

---

## 1. 个性化（session-personalization）

### 作用
控制 AI 是否在新建会话时自动生成简洁的会话标题，以及由哪个模型来生成。

### 包含的设置项
| 设置项 | 作用 |
|---|---|
| 启用会话标题自动生成 | 开启后，新会话首条消息发出后，AI 会自动生成一个标题显示在会话列表。 |
| 模型 | 选择生成标题所用的模型：主力模型 / 快速模型 / 已启用的具体模型。 |

### 适用场景
- 觉得手动给会话起名麻烦，希望 AI 自动命名；
- 会话列表条目变多，需要一眼识别每条对话的主题；
- 想节省 Token，可以让标题生成使用「快速模型」而不是「主力模型」。

### 测试方法
1. 打开「个性化」页，确认「启用会话标题自动生成」开关已开启。
2. 新建一个会话，发送一条包含具体问题的消息（例如：「帮我用 Python 写一个冒泡排序」）。
3. 回到会话列表，几秒后会话标题应自动从「新会话」更新为一句简洁的主题描述。
4. 关闭开关 → 再新建一个会话 → 标题应保持默认（例如用户消息前若干字符），不会自动改写。
5. 在「模型」中选择「快速模型」，发起新会话，确认标题仍能正常生成（验证模型切换生效）。

## 2. 权限管理（session-permissions）

### 作用
控制 AI 在工具调用、工作区搜索、子智能体调度中的确认策略与超时限制。当前页面包含 3 大模块：加速工作区搜索、工具执行行为、工具延迟加载。

> 历史版本的 Computer use（桌面自动化）、浏览器控制（CDP）、调试模式设置已从该页移除，相关代码均已删除或注释。

### 2.1 加速工作区搜索
| 设置项 | 作用 |
|---|---|
| 启用加速工作区搜索 | 启用基于 `flashgrep` 的本地工作区索引搜索；关闭后 BitFun 会回退到原有（更慢的）搜索方式。 |

**适用场景**：工作区文件较多、默认搜索较慢，或需要让 AI 在大量代码中更精确地定位文件。

**测试方法**：在工作区根目录放入若干文件，开启开关后让 AI「在工作区里搜索包含 XXX 的文件」，对比关闭状态下的耗时与结果数量。

### 2.2 工具执行行为
| 设置项 | 作用 |
|---|---|
| 自动执行 | 跳过工具执行前的用户确认步骤（开=AI 调用工具不再每次询问）。 |
| 确认超时 | 等待用户确认工具调用的最长时间（秒），设为 0 表示永不超时。 |
| 执行超时 | 单个工具执行的最长时间（秒），设为 0 表示不限制。子智能体和命令执行工具有各自限制，不受此项约束。 |
| 子智能体批量调度 | 同一回复中多个子智能体启动请求的调度方式：仅安全并发（只并发只读子智能体）/ 强制并行（全部并行但受容量上限约束）。 |
| 子智能体并发上限 | 同时允许并行运行的子智能体数量。 |

**适用场景**：
- 觉得每次工具执行都要点确认太烦，可以打开「自动执行」；
- 担心 AI 卡在某个工具上太久，可以设置「执行超时」；
- 多 Sub-Agent 同时运行时，希望避免互相争抢资源 → 调整「并发上限」与「批量调度」策略。

**测试方法**：
1. 关闭「自动执行」→ 在会话中让 AI 执行一个写文件操作，确认弹出了确认框；打开后再试，应直接执行。
2. 把「确认超时」设为 10 秒，让 AI 提出一个工具调用并保持不点确认，10 秒后应被自动跳过。
3. 把「执行超时」设为 5 秒，让 AI 跑一个会 sleep 10 秒的命令，应被超时终止。
4. 把「子智能体并发上限」设为 1，让 AI 一次启动多个子智能体 → 应串行运行；调回 5 后应能并行。

### 2.3 工具延迟加载（新增）
| 设置项 | 作用 |
|---|---|
| 启用工具延迟加载 | 开启后，仅在需要时才加载部分工具的完整 Schema（包括部分内置工具及所有 MCP 工具）。关闭后会在每次请求中发送启用工具的完整 Schema，配置了大量 MCP 工具会占用较多 Token。 |

**适用场景**：
- 默认开启即可，能显著节省每次请求的 Token 占用，尤其当 MCP 工具数量较多时；
- 仅当你发现某些 MCP 工具或内置工具「没有按预期暴露给 AI」时，可临时关闭以做诊断；
- 想直接把所有启用工具（含延迟加载内置工具及所有 MCP 工具）一次性暴露给模型，可关闭此开关。

**测试方法**：
1. 在 MCP 页接入多个 MCP 服务器（如 `@modelcontextprotocol/server-everything`），保持开关开启。
2. 新建会话让 AI「列出你可用的工具」→ 应只显示当前真正需要的那部分（延迟加载生效）。
3. 关闭开关 → 再次让 AI 列工具 → 列表应明显变长（所有启用工具的 Schema 全部下发）。
4. 重新开启 → 列表应恢复精简。保存设置后应弹「设置已保存」。

## 3. 快捷动作（quick-actions）

### 作用
代码完成后的一键 AI 动作，从聊天窗口左上角的闪电图标触发，AI 自主端到端完成。

### 包含的设置项
- **内置动作**：开箱即用的 Git 工作流动作，可编辑指令、可启用或禁用。
  - 提交（commit）：提交当前所有代码变更。
  - 创建 PR（create_pr）：为当前分支创建 Pull Request。
- **自定义动作**：用户添加自己的快捷指令（label + prompt）。

### 适用场景
- 编码完后常用一句话就能完成的事，例如「提交」「建 PR」「生成单元测试」「写 commit message」等；
- 想把团队约定固化为预设动作（例如「按 Conventional Commits 规范生成提交信息」）。

### 测试方法
1. 进入「快捷动作」→ 确认内置的「提交」「创建 PR」开关默认开启。
2. 新建一个会话，在工作区里随便改两个文件 → 点击聊天窗口左上角的闪电图标 → 选「提交」。
3. AI 应自动识别变更、生成 commit message 并提交（可在 Git 视图核对）。
4. 回到设置页，点「添加动作」→ 起名「生成单元测试」、指令填「请为当前代码变更生成单元测试」→ 保存。
5. 回到会话，再点闪电图标 → 选「生成单元测试」→ AI 应开始为新改动的代码生成测试。
6. 编辑内置动作的指令，确认点击「编辑」能加载原内容并保存成功。

## 4. 审核（review）

### 作用
**控制 Review 在需要扩展覆盖时使用的成本和容量上限**。当前页面已大幅简化，仅保留「容量」面板。**仅在桌面应用中可用**，网页端会显示「Review 容量设置仅在 BitFun 桌面应用中可用」。

> 历史版本的审核策略（快速/标准/深度）、审核员阵容（业务逻辑/性能/安全/架构/前端/质量检查员）、额外审核 Sub-Agent 等设置已从该页移除。当前页面只保留两个数值控制项。

### 包含的设置项
| 设置项 | 作用 | 取值范围 |
|---|---|---|
| 最大并行审核工作 | 严格 Review 同时运行的审核工作上限。调高后可能并行启动更多模型请求，更早触发供应商限流，并增加 Token 消耗。 | 1–16 |
| 容量等待窗口 | 可选审核工作等待供应商容量的时长（秒）；已经运行的检查可能让审核总耗时更长。 | 0–3600，步长 60 |

### 适用场景
- 启动 `/Review` 或扩展覆盖型审核时，担心并行模型请求过多触发供应商限流 → 调小「最大并行审核工作」；
- 担心审核工作长时间卡在排队 → 设置「容量等待窗口」上限，超时直接跳过；
- 觉得审核太慢、希望尽量并发 → 调大「最大并行审核工作」。

### 测试方法（需桌面版）
1. 打开「审核」页 → 应只看到「容量」一个 Section；网页端应显示「仅桌面端可用」。
2. 把「最大并行审核工作」改为 1 → 保存（应弹「审核设置已保存」）→ 触发一次需要扩展覆盖的审核 → 日志中应看到审核工作串行运行。
3. 把数值改为 4 → 再次触发 → 应看到并行启动多个审核工作。
4. 把「容量等待窗口」改为 60 秒 → 触发审核并人为让供应商返回 429/容量不足 → 等待超过 60 秒的审核工作应被跳过。
5. 关掉网络（或断开模型 API），触发审核 → 应能看到错误状态与「重试」按钮；恢复后点「重试」应能加载设置。

## 5. 记忆（memories）

### 作用
控制 BitFun 自动记忆的生成、使用与整理范围。AI 会从已结束的会话中抽取可复用知识，并整合为长期记忆，供后续新会话使用。

### 包含的设置项

#### 基础
| 设置项 | 作用 |
|---|---|
| 自动生成记忆 | 后台从已结束的本地会话中抽取并整理可复用记忆。 |
| 在会话中使用记忆 | 新会话会读取已整理的记忆摘要作为上下文。 |
| 外部上下文处理 | 记忆抽取如何处理使用过 Web 搜索、网页读取等工具的会话：清空外部工具结果 / 允许外部工具结果 / 跳过整个会话。 |

#### 抽取（控制哪些已完成会话进入记忆抽取）
| 设置项 | 作用 |
|---|---|
| 最小空闲时间 | 会话结束后等待多久才允许抽取。 |
| 会话最大年龄 | 超过该天数的会话不再进入抽取（不能大于候选保留天数）。 |
| 单次抽取上限 | 每次启动记忆任务时最多领取多少个会话进行抽取。 |
| 单次扫描上限 | 寻找抽取候选时最多检查多少个已完成会话。 |
| 抽取并发数 | 符合条件的会话最多同时抽取多少个。 |
| 抽取模型 | 从会话中提炼候选记忆所用的模型。 |

#### 整理（控制抽取结果进入长期记忆前的整理范围）
| 设置项 | 作用 |
|---|---|
| 整理候选上限 | 每次长期记忆整理最多使用多少条抽取结果。 |
| 候选保留天数 | 未被使用的抽取结果超过该天数后不再参与整理。 |
| 整理模型 | 用于合并候选记忆并更新长期记忆文件的模型。 |

#### 顶部操作按钮
- 重置记忆设置：把所有记忆相关设置恢复为默认。
- 打开记忆目录：在文件管理器中打开记忆工作区。
- 重置记忆：清空所有记忆数据与工作区文件（**不可撤销**，会弹二次确认）。

### 适用场景
- 希望 BitFun 能记住你的偏好、项目约定、常见坑等，新会话不用每次重复说明；
- 觉得记忆抽取太占资源 / 太频繁 → 调小并发、单次上限、扫描上限；
- 隐私敏感 → 选择「跳过整个会话」让使用过外部工具的会话不进入抽取；
- 想节省 Token → 让抽取与整理使用「快速模型」。

### 测试方法
1. 确认「自动生成记忆」与「在会话中使用记忆」均开启。
2. 与 AI 进行一次有信息量的对话（例如告知项目代码风格、个人偏好），结束会话。
3. 等待超过「最小空闲时间」后（默认 6 小时，可临时调小到 1 小时加速测试）重启 BitFun。
4. 新建会话，问 AI：「你记得我之前说过的代码风格吗？」→ 它应能复述要点。
5. 点「打开记忆目录」→ 应在工作区下展示记忆文件。
6. 点「重置记忆」→ 二次确认后，再问同样的问题 → AI 应不再记得。
7. 把「外部上下文处理」切到「跳过整个会话」→ 让一个会话使用 Web 搜索后结束 → 检查记忆目录，该会话不应被抽取。

## 6. 外部 AI 应用（external-sources，新增）

### 作用
**无需复制，即可使用其他 AI 应用（如 OpenCode、Claude Code、Codex 等）中兼容的工作内容**。BitFun 会自动识别这些外部来源的命令、工具，并在你授权后直接复用，不再手动复制粘贴。

> 该 Tab 取代了历史上「隐藏的 acp-agents」入口，把兼容外部来源的命令、工具审核统一到这一页。**仅桌面应用中可用**，远程工作区暂不支持。

### 包含的模块
1. **已识别来源**：列出 BitFun 检测到的外部来源（OpenCode / Claude Code / Codex 等），显示其位置、作用域、命令数与工具数；每条可单独启用/停用。
2. **等待审核的工具**：来自外部应用、首次加载前需要你确认来源与执行访问范围的工具。会显示：来源根目录、模块文件路径、作用域、执行域、运行时、工作目录、能力（文件/网络/进程/环境变量）等。点「启用工具」后才会激活；点「保持停用」则继续禁用。
3. **已识别工具**：所有工具的统一列表，每条显示当前状态（需要审核 / 已停用 / 已启用 / 需要选择 / 已识别暂不支持 / 运行时不可用 / 加载失败）。点「详情」展开查看完整审核信息；已启用的可「停用模块」。
4. **工具冲突需要选择**：当多个来源提供同名工具时，需要你选一个实现，否则该名称保持不可用。
5. **命令冲突需要选择**：类似上一项，但针对 `/扩展命令`，多个来源提供同名命令时需要你选择。
6. **顶部按钮**：右上角「刷新」可强制重新扫描所有外部来源。

### 工具/来源生命周期状态
| 状态 | 含义 |
|---|---|
| available | 可用 |
| restricted | 受限 |
| degraded | 需要关注 |
| unavailable | 不可用 |
| removed | 已移除 |
| suppressed | 已停用 |
| using_last_valid_version | 使用上一个有效版本 |

### 工具状态
| 状态 | 含义 |
|---|---|
| approval_required | 需要审核 |
| disabled | 已停用 |
| active | 已启用 |
| conflict | 需要选择（与其他来源重名） |
| unsupported | 已识别，暂不支持（运行时不支持的语法或行为） |
| runtime_unavailable | 运行时不可用（如所需 JavaScript 运行时未安装） |
| load_failed | 加载失败 |

### 适用场景
- 已经在用 OpenCode / Claude Code / Codex 等 AI 应用，希望在 BitFun 里直接复用它们的工具或命令，不想重新实现；
- 想从外部来源引入某个特定工具，但要先看清它的来源根目录、模块路径与能访问的资源范围再决定；
- 多个来源提供了同名命令/工具，希望选定一个并固定下来。

### 测试方法
1. **前提**：桌面版 BitFun，且本机已安装并配置过至少一个外部 AI 应用（例如 Claude Code，在用户全局目录或项目里有其扩展）。
2. 进入「外部 AI 应用」Tab → 应在「已识别来源」中看到对应的来源卡片（带位置、作用域、命令数、工具数）。
3. 点击右上角「刷新」→ 应触发重新扫描，按钮文案变为「正在刷新…」→ 完成后回到「刷新」。
4. **启用/停用来源**：在某来源行关掉开关 → 几秒后该来源提供的工具/命令在 BitFun 中不再可见；重新开启 → 恢复可见。
5. **审核工具**：若出现「等待审核的工具」区块，点开一条 → 核对来源根目录、模块路径、能力（文件/网络/进程/环境变量）→ 点「启用工具」→ 该工具状态应变为「已启用」并出现在「已识别工具」列表中。
6. **停用模块**：在「已识别工具」中找一条 active 状态的工具 → 点「停用模块」→ 状态应变为「已停用」。
7. **冲突选择**：如有「工具冲突需要选择」或「命令冲突需要选择」区块 → 点其中一个候选项 → 状态应更新，原冲突提示消失。
8. **网页端**：在浏览器打开 BitFun → 进入该 Tab 应显示「外部来源目前仅在桌面应用中可用」，不展示任何来源列表。

## 7. MCP（mcp-tools）

### 作用
管理 MCP（Model Context Protocol）服务器与 JSON 配置。MCP 服务器可向 AI 暴露额外的工具、资源和提示词，扩展 BitFun 的能力边界。

### 包含的设置项
- **服务器列表**：以卡片形式展示每个 MCP 服务器，可进行启动 / 停止 / 重启 / 删除 / 远程认证。
- **JSON 配置**：通过编辑标准 Cursor 格式的 JSON 来批量管理服务器配置（保存到用户目录下的 `app.json`）。
- **远程认证**：对于远程 MCP 服务，支持 OAuth 登录或粘贴 Bearer token / Authorization 请求头。

### 服务器类型
- 本地进程（stdio）：通过 `command` + `args` 启动一个本地进程。
- 远程服务（sse）：通过 `url` 连接远程 SSE 服务。
- 容器服务：通过容器运行 MCP。

### 适用场景
- 想让 AI 能调用 GitHub、数据库、文件系统等外部能力；
- 团队内部有自建的 MCP 服务，想接入到 BitFun 中；
- 想用一段 JSON 批量复制/迁移其他工具（如 Cursor）的 MCP 配置。

### 测试方法
1. **添加本地 MCP 服务器（最快验证）**：
   - 点右上「JSON 配置」按钮切换到编辑器。
   - 粘贴如下示例并保存：
     ```json
     {
       "mcpServers": {
         "example-local": {
           "command": "npx",
           "args": ["-y", "@modelcontextprotocol/server-everything"]
         }
       }
     }
     ```
   - 列表中应出现 `example-local`，状态从「未初始化」→「启动中」→「已连接」/「健康」。
   - 在会话中让 AI「列出 example-local 提供的工具」，应能看到 MCP 暴露的工具。
2. **测试启停**：点列表项右侧的 ▶ 启动 / ⏹ 停止 / ↻ 重启，状态徽章应随之变化。
3. **测试远程认证**：选一个远程 MCP（如某个需要 Bearer Token 的服务），点钥匙图标 → 粘贴 Token → 保存 → 应自动重连且状态变为「已连接」。
4. **测试 OAuth 流程**（如有支持 OAuth 的远程服务）：点「通过 OAuth 连接」→ 浏览器自动打开授权页 → 完成授权 → 弹窗中状态应依次变为「等待打开浏览器 → 等待回调 → 交换授权码 → 已授权」。
5. **错误处理**：故意把 JSON 改成非法格式 → 编辑器底部应标红并提示「第 X 行，第 Y 列」的语法错误位置。
